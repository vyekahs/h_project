# [기획서] 성악설 기반 게임 예약 및 대기열 시스템

본 기획서는 유저의 자율성보다는 시스템의 제약과 규칙을 통해 공정한 게임 환경을 유지하는 '성악설' 기반의 예약 시스템 구축을 목표로 합니다.

## 1. 핵심 기능 및 운영 규칙 (성악설 기반)

### 🚫 강력한 제약 조건 (Constraints)
*   **1인 1예약 원칙**: 현재 게임 중이거나 이미 다른 게임에 예약된 유저는 추가 예약을 할 수 없습니다. (중복 점유 방지)
*   **참여 인원 미달 시 자동 폭파**: 게임 시작 예정 시간까지 최소 인원(Min Players)이 모이지 않으면 해당 세션은 자동으로 삭제됩니다.
*   **취소 제한 시간**: 게임 시작 10분 전부터는 자유로운 취소가 불가능하며, 취소 시 페널티가 부여됩니다.

### ⚖️ 페널티 및 관리 (Penalty System)
*   **노쇼(No-Show) 자동 처리**: 시작 시간으로부터 10분간 참여 확인이 되지 않으면 예약이 자동 취소되며 페널티 점수가 부여됩니다.
*   **페널티 누적 제재**: 페널티 점수가 일정 수준 이상인 유저는 당일 예약 금지 또는 블랙리스트로 등록되어 관리자의 승인 없이 참여가 제한됩니다.
*   **관리자 블랙리스트**: 악의적인 유저를 관리자가 직접 차단할 수 있는 기능을 제공합니다.

### 🔄 효율적인 순환 (Efficiency)
*   **대기열(Waitlist) 자동 승계**: 예약 취소 발생 시 대기 순번 1번 유저에게 자동으로 참여 권한이 넘어갑니다.
*   **예상 대기 시간 제공**: 현재 진행 중인 게임의 남은 시간을 계산하여 예약자에게 실시간으로 정보를 제공합니다.

## 2. 데이터베이스 설계 변경안

### [MODIFY] [attendees](file:///Users/arang/projects/Hproject/database/schema.sql)
*   `penalty_points`: 유저의 누적 페널티 점수 (INTEGER)
*   `is_blacklisted`: 블랙리스트 여부 (BOOLEAN)
*   `last_penalty_at`: 마지막 페널티 부여 시간 (TIMESTAMP)

### [NEW] `reservations` 테이블
*   `id`: PK
*   `session_id`: 연결된 게임 세션 ID (진행 중인 게임 예약 시 필요)
*   `game_id`: 예약하려는 게임 ID
*   `attendee_id`: 예약자 ID
*   `status`: 상태 (`pending`, `waitlisted`, `confirmed`, `cancelled`)
*   `created_at`: 예약 생성 시간

## 3. 화면별 변경 사항

### 📱 공개 현황판 (Public Board)
*   **진행 중인 게임**: 각 테이블 하단에 "예약하기" 버튼 추가. (현재 게임 종료 후 바로 시작할 인원 모집)
*   **게임 예정 목록**: 새로 개설될 게임 목록과 현재 참여 인원/대기 인원 표시.
*   **참여 신청**: 이름 입력 후 신청 시 시스템이 제약 조건(중복 예약 등)을 체크하여 승인.

### ⚙️ 관리자 대시보드 (Admin Dashboard)
*   **예약 관리**: 전체 예약 현황 모니터링 및 강제 취소 기능.
*   **유저 관리**: 페널티 점수 수정 및 블랙리스트 설정.
*   **설정**: 노쇼 판단 시간(기본 10분), 페널티 기준 점수 등 정책 설정.

## 4. 검증 계획

### 자동화 테스트 및 시나리오
1.  **중복 예약 차단**: 이미 예약된 유저가 다른 게임에 신청 시 에러 메시지 출력 확인.
2.  **노쇼 자동 취소**: 테스트 시간을 조작하여 10분 후 예약이 취소되고 페널티가 부여되는지 확인.
3.  **대기열 승계**: 앞 순번 취소 시 뒷 순번의 상태가 `waitlisted`에서 `pending`으로 변경되는지 확인.
4.  **최소 인원 미달**: 시작 시간 도래 시 최소 인원 미달 세션이 자동 삭제되는지 확인.
