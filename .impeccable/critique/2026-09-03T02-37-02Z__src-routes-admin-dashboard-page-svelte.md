## Design Specificity Verdict

**도메인 문구가 범용 어드민 섀시 위에 얹혀 있다.** 결정적 근거는 미학이 아니라 데이터다.

`Attendee`가 `is_playing`과 `game_name`을 들고 있는데(`:488-489`) 현재 참여 인원은 **둘 다 그리지 않는다**(명단 행이 읽는 것은 name/arrival_time/penalty_points/is_blacklisted/can_manage_games뿐 — 코드 확인). 운영자의 실제 일은 자리 배치인데 명단은 속성 하나만 더 읽으면 답할 수 있는 질문에 평평한 목록으로 답한다.

1280×800의 첫 화면은 헤더 + 스트립 + 큐 전부다. 게임도 사람도 없다. 그 큐의 제목이 스스로 처리 대상 2건이라 말하고 둘 다 「확정 불가」다.

**디텍터 2건 전부 오탐 — 이번엔 원인까지 추적됨.**
- `flat-type-hierarchy`는 측정이 아니라 이름 충돌. Tailwind 클래스 맵을 `\btext-lg\b`로 매칭하는데 `--text-lg`의 `-`가 비단어 문자라 CSS 변수 선언 이름이 걸린다. `--text-lg`(20px)를 18px로, `--text-xl`(24px)을 20px로 잘못 읽고 `--text-stat`(40px)은 놓친다. 실제 스케일 12/14/16/20/24/40 = 3.33:1로 규칙 자체 기준(2.0)을 넘는다.
- `monotonous-spacing`은 `var()`를 못 읽어 리터럴 15개만 샘플링했고 그중 14개가 사이드바 아이콘의 인라인 margin이다.
- 계산 스타일을 읽는 브라우저 디텍터는 둘 다 보고하지 않았다(독립 확인).

## Overall Impression

지난 라운드의 접근성 작업은 계측으로 검증하면 실제로 버틴다 — 가로 오버플로 0, 포커스 링 24개 전부 표시(16.27/17.74/6.21:1), 모달 3개 Tab 탈출 0회·Escape·복원·스크롤 잠금, 라이브 리전 4개 모두 사전 존재, 섹션·nav 전부 이름 있음.

문제는 점수가 다섯 회차째 20대 초반이라는 것이고 이유가 분명해졌다. 매 라운드가 문제를 **옮겼다**. 파란 버튼 일색 → 회색 두 뜻 충돌. 취소/취소 동음이의 → 제목/버튼 충돌. 밋밋한 만료 행 → 뒤집힌 틴트. 요소 단위로는 맞는 답을 내는데 섹션 순서와 단일 컬럼이라는 뼈대는 한 번도 안 건드렸다.

## Priority Issues

### [P1] 첫 화면에 방도 게임도 없다
1280×800 첫 화면이 헤더+스트립+큐 전부. 모바일은 ~660px 스크롤해야 게임이 나온다. 큐 제목이 스스로 (2)라 말하고 둘 다 확정 불가.
제품의 존재 이유가 실시간 시인성인데 대부분 손댈 수 없는 인박스를 지나야 「누가 있고 뭐가 돌고 있나」에 닿는다. `:729` 주석은 인박스 멘탈 모델의 최적화다.
**Fix**: ≥1024px에서 게임+인원을 스트립 아래 2열로, 큐는 오른쪽/아래로. 모바일은 큐를 한 줄 요약 바로 접는다. 데스크톱 오른쪽 40%가 비어 있어 자리는 이미 있다. → `$impeccable layout`

### [P1] 가장 자주 쓰는 세 동작이 아무 응답도 하지 않는다
`joinGame`(:1723) `addGuestToGame`(:1735) `extendGame`(:1748)이 `reportResult`만 부르고 성공 문구를 안 넘긴다 → 토스트 없음(코드 확인). 파일 자체 주석이 「조용히 끝나는 폼이 없게 하는 것이 목적」이다.
시끄러운 방에서 눌린 건지 몰라 다시 누르면 +20분이 된다. extendGame에는 되돌리기도 시간 단축도 없어 유일한 교정이 게임 종료다.
**Fix**: `pending`에 성공 문구. `−10분` 추가. → `$impeccable harden`

### [P1] 백드롭 한 번 탭이 채운 폼을 말없이 버린다 — 엄지 자리에서
375px에서 입력을 채운 새 게임 시작이 (40,790) 클릭에 사라진다(4종 모달 모두). 백드롭(z1000)이 하단 탭 바(z100)를 덮는데 탭 바는 흐려지지 않고 선명한 채 기능만 죽어, 누르면 작성 중이던 시트가 닫힌다.
정확히 제품이 상정한 장면(한 손·폰·시끄러운 방)에서 인터페이스가 거기를 누르라고 초대해 놓고 작업을 버린다.
**Fix**: 입력 있는 모달은 백드롭 비활성 또는 「입력한 내용이 사라집니다」. 모달 중 탭 바를 흐리게. → `$impeccable harden`

### [P1] 관리 시트에서 심각도와 시각적 무게가 반대다
확인 사다리(코드 확인): 매니저 지정(:1420) 확인창 없음·되돌리기 없음 / 블랙 등록(:1407) 확인창 있음·되돌리기 **없음** / 게임 종료 확인창 없음·되돌리기 **있음**. 실제 심각도와 정반대다.
블랙 등록이 시트 최강색이고, 퇴장 처리가 네이티브 시트의 "완료" 자리에 있어 닫으려 손을 뻗으면 거기 닿는다. `adminUndo` 인프라는 이미 있다.
**Fix**: 블랙 등록을 빨간 테두리로, 닫기를 하단 전폭으로, 퇴장 처리를 속성 행들과 함께 위로. 블랙 등록에 `toastUndoable`, 매니저 지정에 확인창. → `$impeccable polish`

### [P2] 직전 라운드에 만든 회귀 세 건
- **hover에서만 대비가 깨진다**: `#c2410c`가 `#fff3e0`에서 4.722인데 새로 넣은 `--color-warning-bg-strong: #ffeccc`에서 **4.469**. 토큰 옆에 「hover 틴트는 4.5:1을 지키는 선까지만」이라고 주석까지 달고 빨강 짝(4.552)만 확인했다.
- **`<AdminFeedback />`가 `.force-light` 밖**: 래퍼가 :159-160에서 닫히는데 컴포넌트는 :162. `:global(.force-light :focus-visible)`이 안 닿아 **되돌리기 버튼 포커스 링이 Chromium 기본값으로 `#555` 위 1.25:1**. 같은 이유로 그 컴포넌트의 `var(--토큰, 폴백)`이 전부 폴백으로 해석된다.
- **되돌리기 버튼 74.5×32** — 44×44 미달. 실수를 무르는 버튼이 가장 작은 축이다.
- 오래된 것: `.list-arrow`(`›`)가 `--text-muted`로 흰 배경 **2.849:1**, 만료 행 hover 위 2.46:1. 20px bold라 3:1 적용, 방향 지시자라 1.4.11로도 3:1. 양쪽 미달.
→ `$impeccable audit`

## Questions to Consider

1. 명단은 이미 `is_playing`과 `game_name`을 알면서 둘 다 안 그린다. 진짜 일이 다음에 누굴 앉힐지 정하는 것이라면 왜 평평한 목록인가?
2. 다시 시작하면 그만인 게임 종료에 되돌리기가 붙고 사람을 배제하는 블랙 등록에는 안 붙었다. 어떤 축으로 정한 것인가?
3. 「대기 중 0」이 증명 가능하게 비어 있는데 그게 올바른 기본 범위라면 세그먼트는 무엇을 위한 것인가? 채워진 쪽이 선택 안 된 쪽이라면 누가 쓰는 걸 본 적 있는가?
4. 스트립이 1,024px로 두 단어 레이블 셋을 담고 아래로 4,400px을 스크롤한다. "필요한 전부가 스크롤 없이 폰 한 화면에"가 제약이면 이 화면은 어떤 모습인가?
5. 다섯 크리틱·네 수정이 23/40에 붙들려 있고 매번 문제가 옮겨졌다. 남은 빚이 요소 단위로 고칠 수 있기는 한가, 아니면 섹션 순서와 단일 컬럼을 방에서부터 다시 세워야 하는가?
