## Design Specificity Verdict

**LLM 평가**: "장식장" 은유(정사각 커버+잠금/소장 배지), "혼놀 보유 여부와 무관한 자가 소장 체크" 개념 분리, "함께한 날짜 수" 기준 친구 랭킹(같은 날 여러 판 과대평가 방지 — 주석에 의도 명시), 7일 수정 기간 등은 실제 동아리 운영 경험에서 나온 규칙이라 범용 템플릿이 아닙니다. 다만 시각적으로는 "정사각 커버 그리드 + 필터 드롭다운 + 모달"이라는 조합 자체가 흔한 패턴이고, 소장=집 모양·미플레이=자물쇠 아이콘은 범용 아이콘 세트를 그대로 가져다 쓴 티가 나서, "장식장"이라는 이름값에 비해 진열장다운 질감(선반, 여백의 의미, 수집 완료 시 특별 처리)은 아직 약합니다.

**결정론적 스캔**: `detect.mjs --json src/routes/collection` → exit 2, 총 2건(둘 다 warning).
- `side-tab` (`+page.svelte:1108`, `.modal-play-row.win { border-left: 3px solid var(--color-amber); }`): 룰 자체는 정탐이지만, 바로 위 코드 주석에 색상 선택 근거(WCAG 대비 계산)가 명시된 **의도가 문서화된 예외**입니다. 조치 불필요.
- `layout-transition` (`+page.svelte:693`, `.progress-fill { transition: width 0.3s ease; }`): 격리된 작은 바(`overflow: hidden` 컨테이너 내부)라 실질적 레이아웃 스래싱 위험은 낮지만, `transform: scaleX()` + `transform-origin: left`로 바꾸면 GPU 합성 레이어를 타 기술적으로 더 안전합니다. 저위험이지만 정당한 지적.

detect.mjs가 정적 분석으로는 잡을 수 없는 항목(CSS 커스텀 프로퍼티 조합의 실제 렌더링 대비)은 브라우저 실측에서 별도로 발견되었습니다 — 아래 우선순위 이슈 참고.

**브라우저 오버레이**: 그리드(라이트/다크)·모달·전체 기록·모바일 5개 뷰에 실시간 주입 성공. 다크 모드 그리드 뷰에서 `low-contrast(2.5:1, need 4.5:1)` 오버레이가 "게임별" 활성 탭 버튼과 플레이 횟수 배지("×2") 위에 정확히 표시되었고, 실제 CSS를 대조한 결과 `.play-badge`(770-778행)와 `.view-toggle button.active`(885-889행)가 공통 원인으로 확인되었습니다(아래 우선순위 이슈 참고). `gpt-thin-border-wide-shadow`와 `oversused-font(roboto)`는 전 뷰에서 반복 검출되었지만, 스크린샷 대조 결과 대상이 이 페이지가 아니라 **전역 하단 네비게이션 바/공용 레이아웃**이라 이번 critique 범위(`src/routes/collection`) 밖으로 판단해 제외했습니다.

## Overall Impression

"장식장"이라는 컨셉 자체와 그 밑을 받치는 데이터 규칙(소장 분리, 친구 랭킹 로직, 수정 기간)은 실제 제품 맥락에서 나온 진짜 설계입니다. 문제는 두 층위에서 옵니다: 첫째, **이 페이지의 존재 이유인 "내 기록을 정확히 보여주기"가 실제로는 조용히 깨져 있다**(아래 P0). 둘째, 지난 라운드에서 대비·필터 노출 문제를 고쳤음에도 **같은 부류의 문제(다크모드 저대비, 은유와 동작의 불일치, 정보 과다 노출)가 다른 요소에서 반복**되고 있어, 개별 수정보다 패턴 차원의 재점검이 필요해 보입니다.

## What's Working

- **`stateVersion` 없이도 서버 액션 → `update()` → `$derived` 재계산이 매끄럽게 연결됨**: 소장 토글·기록 수정 모두 폼 제출 후 즉시 반영되어, 별도 낙관적 업데이트 로직 없이도 반응성이 나쁘지 않습니다.
- **필터 기본 접힘 + 활성 개수 배지**: 지난 크리틱에서 지적된 "필터가 기록보다 눈에 띈다"는 문제를 실제로 해결했습니다. 다만 펼쳤을 때의 컨트롤 개수 자체는 그대로라 부분적 해결에 그칩니다(P2 참고).
- **`playRow` 스니펫 공유**: 게임별 모달과 전체 기록이 같은 행 컴포넌트를 써서 두 화면을 오가도 기록의 생김새가 흔들리지 않습니다 — 일관성 측면에서 견고한 구현 선택.

## Priority Issues

**[P0] 실제 플레이 기록 대부분이 게임명 문자열 불일치로 조용히 누락됨**
- What: `+page.server.ts`의 매칭 쿼리가 `gs.game_id = g.id` 또는 `gs.game_id IS NULL AND gs.game_name = g.name`(정확 일치)로 카탈로그와 연결합니다. attendee 14의 실제 세션 17건 중 15건이 `game_name = '티츄'`인데 카탈로그의 이름은 `'티츄 (Tichu)'`라 정확 일치에 실패해 매칭되지 않습니다 — DB 직접 조회로 확인.
- Why it matters: 이 페이지의 핵심 가치는 "내가 플레이한 기록을 빠짐없이 보여주는 것"입니다. 그런데 실제 계정에서 17건 중 2건만 화면에 나타나고, 사용자는 자신의 기록이 누락됐다는 사실조차 알 방법이 없습니다(오류도, 경고도 없이 조용히 사라짐). 오래된 세션일수록 게임명이 정확한 카탈로그 표기와 다를 가능성이 높아, 활동 이력이 긴 사용자일수록 더 크게 손해를 봅니다.
- Fix: 정확 일치 대신 정규화 비교(공백/괄호 제거 후 부분 일치, 또는 트라이그램 유사도)로 완화하거나, 근본적으로는 세션 생성 시 `game_id`를 항상 채우도록 강제하고 과거 데이터는 일회성 백필 스크립트로 정리하는 편이 안전합니다.
- Suggested command: 디자인 명령 범위 밖입니다 — 데이터/쿼리 로직 수정이 필요한 코드 이슈입니다.

**[P1] 다크 모드에서 흰 텍스트 대비가 WCAG AA 미달인 요소가 두 곳 더 있음**
- What: `.play-badge`(770-778행)와 `.view-toggle button.active`(885-889행)가 `background: var(--color-blue); color: #fff;`를 씁니다. `--color-blue`는 다크 모드에서 `#4dabf7`로 바뀌는데(`+layout.svelte:328`), 흰 텍스트 대비를 직접 계산하면 **2.51:1**로 4.5:1 기준에 못 미칩니다. 지난 라운드에서 고친 승리 배지와 같은 부류의 버그입니다 — `--color-blue`도 `--color-amber`와 달리 라이트/다크 값이 다르게 정의돼 있어(`#1864ab` vs `#4dabf7`) 같은 함정에 빠진 것으로 보입니다.
- Why it matters: 플레이 횟수 배지와 뷰 전환 활성 탭은 그리드/모달을 여는 거의 모든 화면에서 상시 노출되는 요소라, 노출 빈도로 보면 지난번 고친 승리 배지보다 오히려 영향 범위가 넓습니다.
- Fix: `--color-blue`를 텍스트-배경 쌍으로 재사용하는 대신, 지난번과 같은 패턴으로 라이트/다크 값이 동일한 토큰(또는 다크 전용 진한 텍스트색)으로 교체해 두 테마 모두 4.5:1 이상을 확보하세요.

- 데스크톱(1280px 이상, `repeat(6, 1fr)` 그리드)에서 보유 게임이 4~5종처럼 적으면 그리드 하단이 텅 빈 회색 여백으로 남습니다 — 신규/저활동 회원일수록 화면이 미완성처럼 보이는 역설이 생깁니다.
- "게임별" ↔ "전체 기록" 전환 시 컨트롤의 위치·종류가 통째로 바뀝니다(검색창+체크박스 vs 필터 디스클로저) — 학습된 동선이 모드마다 리셋됩니다.
- `search-clear`(✕ 버튼)와 `filter-disclosure-toggle`의 실제 탭 영역이 44px 권장 터치 타깃보다 작아 보입니다(패딩 0.3~0.35rem 수준).
- `.progress-fill`의 `transition: width`는 `transform: scaleX()`로 바꾸면 레이아웃 스래싱 없이 같은 효과를 냅니다(detect.mjs 정탐, 저위험).
- 승자 체크박스 조합에 서버 측 제약이 코드상 확인되지 않아, 0명 체크 같은 비정상 상태도 저장될 여지가 있습니다.

## Questions to Consider

- "장식장" 은유를 끝까지 밀어붙인다면 어떨까요 — 실제 진열장처럼 빈 자리의 여백·질감을 더 써서 "수집욕"을 자극하는 방향은요?
- 7일 수정 기간을 못 박고 조용히 버튼을 없애는 대신, 마감이 다가올 때 미리 알려주는 방식("3일 남음")이었다면 이번에 발견한 감정적 골짜기가 애초에 생기지 않았을까요?
