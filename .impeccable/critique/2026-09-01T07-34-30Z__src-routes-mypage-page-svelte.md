## Design Specificity Verdict

여전히 "잘 만든 Operate 화면 보일러플레이트"에 가깝습니다 — 카드+섀도우+탭 4개+공유 모달이라는 구조는 어느 SaaS 관리 화면에 옮겨도 위화감이 없습니다. 다만 3라운드에 걸쳐 누적된 도메인 디테일(칭호 뱃지, 시즌패스 만료 유예, "체크된 사람은 검색 중에도 유지"라는 명시적 데이터 보존 설계)은 이 제품의 실제 규칙을 반영해 완전히 일반적이지는 않습니다. 이번 라운드의 진전은 겉모습이 아니라 행동에서 있었습니다 — 포커스 트랩과 라이트모드 대비가 실제로 고쳐졌습니다. 하지만 그 작업을 하며 건드린 바로 그 파티 모달에서 새 라이브 버그(게임 드롭다운 고착)가 나왔고, 그 대비 수정 자체도 다크모드에서는 검증되지 않았던 것으로 드러났습니다.

**디텍터 스캔**: CLI 1건(`side-tab`, 승리 카드 앰버 보더) — 4라운드 연속 동일 판정으로 허위양성 확정. 라이브 오버레이에서 `text-occlusion` 1건이 추가로 잡혔으나, 스캔 결과 해당 span의 rect가 0×0이고 텍스트가 다른 finding의 설명 문구 그 자체 — **디텍터가 자신이 주입한 주석 엘리먼트를 재스캔한 도구 자체 아티팩트**로 두 에이전트 모두 실제 버그 아님으로 판정. `gpt-thin-border-wide-shadow`(하단 nav)와 `overused-font`(body 전역)는 mypage 파일 범위 밖(공유 레이아웃/전역 폰트).

## Overall Impression

3라운드 연속으로 총점이 28/40에 고정돼 있지만, 매번 "무엇이 28점을 만드는지"는 달라졌습니다 — 2라운드는 확인 모달 회귀, 3라운드는 히든 인풋 포커스 버그, 이번엔 게임 드롭다운 고착과 다크모드 대비 회귀. 매 라운드 정확히 하나씩 새로운 결함이 이전 라운드가 고친 자리 바로 옆에서 나타나는 패턴입니다. 특히 이번엔 **두 서브에이전트가 완전히 다른 방법(라이브 재현 vs. CSS 커스텀 프로퍼티 소스 계산)으로 같은 결론(다크모드 배지 대비 2.77:1 실패)에 독립적으로 도달**했다는 점이 신뢰도를 높입니다. 반대로 좋은 소식도 있습니다 — 3라운드의 P1(포커스 트랩)과 P2(친구 목록 truncate, 멤버 검색 DOM 필터링)는 이번엔 양쪽 에이전트 모두 명확히 PASS로 확인했습니다.

## What's Working

1. **멤버 검색의 "체크된 사람은 검색어와 안 맞아도 유지" 로직이 실제로 견고합니다.** 코드 주석과 실제 동작이 정확히 일치했고(체크→비매칭 검색→유지, 언체크→비매칭 검색→소멸), B가 DOM 레벨에서 실제 노드가 6개→2개로 줄어드는 것까지 확인해 데이터 유실 방지가 말뿐이 아님을 검증했습니다.
2. **trapFocus의 히든 인풋 제외 수정이 5개 모달에서 일관되게 작동합니다.** 파티 모달에서 Tab 0회 상태로 Escape를 눌러도 즉시 닫히는, 정확히 3라운드에서 실패했던 시나리오가 고쳐졌음을 두 에이전트가 각각 확인했습니다.
3. **파괴적 액션 확인 카피가 결과를 구체적으로 설명합니다.** "삭제하면 이 기기로는 더 이상 자동 체크인이 되지 않습니다" 같은 문구는 여전히 이 페이지의 대표적인 강점입니다.

## Priority Issues

**[P2] 다크모드에서 알림 배지 대비가 2.77:1로, 수정 전(3.76:1)보다 오히려 더 나빠짐**
- **왜 문제인가**: 라이트 테마에선 `--color-red-dark`가 `#d32f2f`로 실제로 어둡지만, 다크 테마 블록(`+layout.svelte` 258행 이하)에서는 `--color-red-dark`가 `--color-red`와 동일한 `#f87171`로 앨리어싱되어 있습니다. `NotificationBell.svelte`의 `.badge`(흰 텍스트 on `--color-red-dark` 배경)는 다크모드에서 흰 텍스트 대 `#f87171` = **2.77:1**로 AA(4.5:1)에 크게 미달 — 라이트모드에서 지적됐던 원래 문제(3.76:1)보다도 나쁩니다. `app.html`의 테마 초기화 스크립트는 `localStorage`에 저장된 테마가 없으면 OS의 `prefers-color-scheme`를 그대로 따르므로, 이건 엣지 케이스가 아니라 OS를 다크모드로 쓰는 상당수 실사용자에게 기본 노출됩니다. 두 서브에이전트가 완전히 다른 방법(A: 코드 계산, B: 실제 페이지에서 CSS 변수 값 라이브 확인 + 독립 계산)으로 같은 결론에 도달했습니다.
- **Fix**: `--color-red-dark`를 "배경+흰 텍스트" 용도로 재사용하는 패턴 자체가 위험합니다. 다크모드 전용 배지 배경 토큰(예: `--color-red-darker: #dc2626` 계열)을 새로 정의하거나, 시맨틱 토큰(`--status-danger-bg`)으로 분리해야 합니다.
- **Command**: `$impeccable harden`

**[P2] 파티 모달 게임 검색 드롭다운이 다른 필드로 포커스가 이동해도 닫히지 않음**
- **왜 문제인가**: `partyGameDropdownOpen`을 `false`로 되돌리는 경로가 `selectPartyGame()`(게임을 실제로 선택했을 때)뿐입니다. 게임 검색에 입력한 뒤 팟 이름 필드를 클릭해 포커스를 옮겨도 드롭다운은 화면에 그대로 남습니다. 게임이 4개 이상 매칭되면 드롭다운이 멤버 선택 섹션 전체를 가리고, 특히 모바일(390px)에서는 화면 비율상 더 크게 덮어버려 스크롤로도 해소되지 않습니다(`position: absolute`). 게임 필드는 "선택사항"이라 표시돼 있는데 실제로는 드롭다운을 닫으려면 게임을 하나 골라야만 하는 상황이 생겨, 라벨과 실제 압박감이 모순됩니다. 부수적으로 Tab을 눌러 다음 필드로 가려 하면 드롭다운이 열려있는 한 게임 옵션 목록(`role="button"`) 속으로 포커스가 흡수돼 키보드 사용자의 탭 순서도 어긋납니다.
- **Fix**: 게임 검색 wrapper 바깥 클릭 감지(`click-outside` 액션 또는 `svelte:window on:click`으로 타깃 판별) 또는 다른 필드에 포커스가 갈 때(`on:focus`) 드롭다운을 닫는 핸들러 추가.
- **Command**: `$impeccable harden`

**[P2] 멤버 검색 필터가 기본(빈 검색어) 상태에서는 전혀 걸러내지 않음 — 3라운드 인지 부하 위반이 완전히 해소되지 않음**
- **왜 문제인가**: `filteredPartyMembers`의 조건은 `partyMemberIds.includes(a.id) || a.name.includes(partyMemberSearch)`인데, `partyMemberSearch`가 빈 문자열이면 모든 이름이 빈 문자열을 포함하므로 필터가 통과-전부를 의미합니다. 라이브 확인 결과 모달을 열자마자(타이핑 전) 6개 체크박스가 그대로 다 보였습니다. 3라운드에서 지적한 "인지 부하 기준(≤4개) 초과"는 사용자가 능동적으로 타이핑해야만 해소되는 조건부 완화일 뿐, 화면을 처음 마주하는 순간(resting state)의 위반 자체는 그대로 남아있습니다.
- **Fix**: 검색어가 비었을 때는 체크된 멤버(본인 포함)만 기본 노출하고 "+ N명 더 보기"나 검색 유도 placeholder를 강조하거나, 자주 만난 상위 4명만 기본 노출 후 검색으로 확장하는 방식으로 진짜 기본 노출 개수를 줄여야 합니다.
- **Command**: `$impeccable optimize`

**[P3] 건의사항 전송 실패가 사용자에게 전혀 알려지지 않음**
- **왜 문제인가**: `sendFeedback`은 실제 서버 응답을 기다리지 않고 무조건 성공 모달("전송 완료!")을 띄우며, 실패는 콘솔에만 로그됩니다. 사용자는 실패해도 성공했다고 믿게 됩니다.
- **Fix**: `fetch` 응답을 확인해 실패 시 인라인 에러로 전환(이미 파티 모달·칭호 액션에 있는 동일 패턴 재사용 가능).
- **Command**: `$impeccable harden`
