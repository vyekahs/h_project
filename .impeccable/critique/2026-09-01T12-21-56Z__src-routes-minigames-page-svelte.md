## Design Specificity Verdict

**LLM 평가**: 명백히 "생성형 게임 포털 보일러플레이트"에 가깝습니다. 헤더 타이틀이 "Game Lounge"라는 제품명과 무관한 영문 표기이고, 클릭해 들어간 게임 시작 페이지 헤더도 "Sudoku"입니다. 앱 아이콘 그리드+glassmorphism 카드+그라디언트는 어디서나 볼 수 있는 표준 게임 허브 패턴이며, 보드게임 동호회라는 이 제품의 구체적 맥락을 드러내는 요소가 거의 없습니다. 유일하게 고유성이 드러나는 활동 티커·순위 배지조차 영문 UI 텍스트와 뒤섞여 브랜드 목소리가 일관되지 않습니다. PRODUCT.md가 명시한 허브 화면의 "이모지+한글 제목" 컨벤션도 정작 페이지 대표 타이틀에서는 지켜지지 않습니다.

**디텍터 스캔**: CLI 0건(clean, 첫 라운드라 기존 오탐 이력 없음). 라이브 오버레이는 8건 잡았으나 6건이 도구 자체의 판단 오류로 확인됨(그라디언트 배경을 못 읽어 SVG 장식 글리프를 "1.0:1"로 오판 3건, accentColor를 "cyan"으로 잘못 라벨링 3건 — 실제로는 초록/보라). 1건(`gpt-thin-border-wide-shadow`, 하단 nav)은 파일 범위 밖. **1건은 실제 결함으로 확인**: h1에 선언된 `font-family: 'Outfit'`이 앱 어디에도 로드하는 코드(`<link>`/`@font-face`)가 없어 항상 조용히 `sans-serif`로 폴백되고 있습니다 — 의도한 타이포그래피가 사실상 한 번도 적용된 적이 없습니다.

## Overall Impression

첫 라운드치고 명확한 구조적 문제들이 나왔습니다. 가장 시급한 건 이 라우트가 앱 전역 다크모드 설정을 무시하고 강제로 라이트 테마를 씌운다는 점 — 실제로 라이브 확인 결과 페이지 본문은 밝은데 그 아래 하단 탭바는 어둡게 남아 뚜렷한 시각적 이음매가 생깁니다. 그다음으로 심각한 건 게이미피케이션의 핵심인 순위 배지가 10개 게임 중 5개의 accentColor에서 대비가 완전히 무너진다는 것(1.5~2.5:1) — 이번 테스트 계정엔 순위 데이터가 없어 라이브로는 못 봤지만 소스 계산으로 확실히 확인됐습니다. 인지 부하 관점의 "전체 게임 청킹 부재" 지적은 방향은 맞지만, 실제 파일엔 현재 10개 게임만 활성화돼 있어(18개+는 PRODUCT.md의 향후 로드맵) 지금 당장 레이아웃이 깨지는 건 아니라는 점은 감안해야 합니다 — 그래도 로드맵대로 게임이 늘어나기 전에 손보는 게 맞는 구조적 이슈입니다.

## What's Working

1. **활동 티커의 사회적 증거 배치** — 페이지 최상단, 그리드보다 먼저 "지금 누가 뭘 했는지"를 보여줘 시인성 가치와 방향이 맞는 유일한 요소.
2. **인기/신규 vs 전체 게임의 레이아웃 구분** — "지금 볼만한 것"과 "전체 카탈로그"를 암묵적으로 나눈 시도(다만 청킹 실패로 효과가 희석됨).
3. **순위 배지(#1 크라운)** — 게임을 안 해도 그리드를 훑는 것만으로 랭킹 노출, 포인트 시스템과 허브 화면을 가볍게 연결하는 좋은 디테일(다만 대비 결함으로 실효성 훼손 — 아래 참고).

## Priority Issues

**[P0] 다크 테마가 이 라우트에서 강제로 무시됨**
- **왜 문제인가**: `src/routes/minigames/+layout.svelte`가 라이트 테마를 하드코딩하고 있어, 앱 전역 다크모드 설정과 무관하게 오락실 진입 순간 무조건 라이트로 전환됩니다. 라이브 확인 결과 페이지 본문은 라이트인데 하단 탭바(홈/보드게임/오락실/마이페이지)는 다크로 남아 뚜렷한 시각적 이음매가 생깁니다. 동호회 모임이 저녁 시간대가 많아 다크모드 사용자 비중이 낮지 않을 텐데, 오락실에 들어갈 때마다 눈부심이 생깁니다.
- **Fix**: 라이트 강제 클래스와 CSS 변수 오버라이드를 제거하고 전역 테마 토큰을 상속받게 함. 라이트 강제가 정말 필요한 이유(게임 렌더링/에셋 문제 등)가 있다면 주석으로 남기고 범위를 최소화.
- **Command**: `$impeccable audit`

**[P1] 순위 배지 대비가 10개 게임 중 5개에서 완전히 무너짐 (1.5~2.5:1)**
- **왜 문제인가**: `.rank-badge`는 `color: var(--accent)`(게임별 고유색) on `background: rgba(255,255,255,0.95)`를 씁니다. 스도쿠(2.50:1)·킬러스도쿠(1.51:1)·티츄(2.24:1)·에너지서킷(2.11:1)·2048(1.67:1) 다섯 게임의 accentColor가 전부 4.5:1 미달이고, 1위 크라운 배지(흰 텍스트 on amber 그라디언트)도 1.67~2.15:1로 실패합니다. 폰트가 9.6~12px라 large-text 예외도 못 받습니다. 이번 테스트 계정엔 순위 데이터가 없어 라이브 렌더는 못 봤지만 실제 accentColor 값으로 계산해 확정된 결함입니다.
- **Fix**: 배지 텍스트 색을 accentColor 그대로 쓰지 말고, 각 accentColor의 어두운 변형(다크 배리언트)을 쓰거나 배지 배경을 accentColor로, 텍스트를 고정 흰색/검정으로 바꿔 대비를 보장.
- **Command**: `$impeccable harden`

**[P1] 인기/신규 섹션 중 하나만 데이터가 있을 때 2열 그리드가 절반 비어버림**
- **왜 문제인가**: `featured-row`가 `grid-template-columns: 1fr 1fr`로 고정돼 있고 두 섹션이 각각 조건부 렌더링됩니다. 실제 테스트 계정(인기 게임 데이터 없음)에서 재현: "새로운 게임" 섹션만 왼쪽 칸에 렌더되고 오른쪽 절반이 완전히 빈 공간으로 남습니다. 모바일/데스크톱 둘 다 동일하게 깨집니다. 인기 게임 데이터가 없는 상태(신규 시즌 시작, 랭킹 집계 초입 등)는 드물지 않습니다.
- **Fix**: 한쪽만 있을 때 `grid-template-columns: 1fr`로 전환하거나 `grid-column: span 2` 폴백 적용.
- **Command**: `$impeccable harden`

**[P2] 헤더 h1에 선언된 'Outfit' 폰트가 어디서도 로드되지 않아 항상 폴백됨**
- **왜 문제인가**: `.glass-title-badge h1`에 `font-family: 'Outfit', sans-serif`가 지정돼 있지만, `app.html`이나 전역 레이아웃 어디에도 Outfit을 로드하는 `<link>`나 `@font-face`가 없습니다(`grep -rln "Outfit"` 결과 이 선언이 있는 파일 2개뿐, 로딩 코드 0건). Outfit이 로컬에 우연히 설치된 사용자를 제외하면 전원이 조용히 `sans-serif`로 폴백 — 의도한 타이포그래피가 사실상 적용된 적이 없습니다. "Game Lounge"라는 영문 타이틀에 힘을 실어주려 했을 디스플레이 폰트가 애초에 작동 안 하는 것.
- **Fix**: Google Fonts 등에서 Outfit을 실제로 로드하거나, 로드할 계획이 없다면 이미 프로젝트에서 쓰는 폰트로 `font-family` 값을 교체.
- **Command**: `$impeccable harden`

**[P2] "Coming Soon" 라벨이 opacity 합성으로 실제 대비 ~2.3:1까지 떨어짐**
- **왜 문제인가**: `.game-icon-item.coming-soon`에 `opacity: 0.5`가 걸려있어, 라벨 텍스트 색이 계산상으론 7.17:1이지만 실제 렌더링(배경과 50% 블렌딩) 후에는 약 2.3:1로 떨어집니다. 스크린샷으로도 글자가 배경에 거의 묻혀 보입니다.
- **Fix**: opacity로 "비활성" 느낌을 주는 대신 색상 자체를 흐리게 하거나, 텍스트에는 opacity가 적용 안 되게 분리.
- **Command**: `$impeccable polish`

## Questions to Consider

1. "전체 게임" 그리드를 알파벳/등록순이 아니라 "지금 클럽룸에 있는 사람이 가장 많이 하는 게임" 같은 실시간 시인성 데이터로 정렬한다면, 오락실이 진짜 "지금 여기 누가 뭘 하고 있는지" 보여주는 창이 될 수 있지 않을까요?
2. 오락실 안에서 완결되는 지금 구조 대신, 신규 게임 알림을 "메인 대시보드로 돌아가면 확인 가능"하게 설계하면 PRODUCT.md가 원하는 "메인 화면 복귀" 유도 장치가 될 수 있지 않을까요? 지금은 오락실에 들어온 사용자를 다시 메인으로 끌어당길 장치가 하나도 없습니다.
3. 일반적인 장르 필터 대신 "2인 이하로 지금 할 수 있는 것" / "혼자 킬링타임" 같은 동호회 맥락의 상황별 태그로 18개+ 게임을 묶으면, 훨씬 "이 제품다운" 발견 경험이 되지 않을까요?
