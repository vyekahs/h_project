## 디자인 고유성 판정

**LLM 평가**: 절반은 고유하고, 절반은 플레이어가 가장 많이 보는 곳에서 일반화됨. 주변 장식(제국풍 금색 그라디언트, 드래곤/봉황 아이콘, 한국어 용어, 튜토리얼)은 확실히 이 제품을 위해 만들어진 것들. 하지만 세션의 90%를 차지하는 카드 자체는 표준 프랑스식 문양(♣♠♦♥)에 티츄의 중국풍 문양 이름을 데이터에만 붙여놓은 형태 — 아트워크에는 전혀 반영이 안 됨. 이 카드 페이스만 놓고 보면 어떤 카드게임이든 그대로 가져다 써도 티가 안 날 정도.

**결정론적 스캔**: `detect.mjs`가 티츄 라우트 전체에서 **45건**을 찾음 (전부 "slop"/품질 카테고리):

**비주얼 오버레이**: 스크립트 주입은 성공했고 브라우저 콘솔 결과도 수집됨(설정 화면 10건, 라이브 플레이 테이블 11건 — 구체적인 내용은 아래 우선순위 이슈 참고). 다만 이번 실행에서는 사용자에게 보이는 오버레이 탭은 없었음 — 서브에이전트가 백그라운드/헤드리스 Playwright 스크립트로 작업해서, 실시간 화면 오버레이가 아니라 콘솔 로그 텍스트로만 증거가 남음.

## 전체적인 인상

"너무 빨간색이라 부담스럽다"는 피드백은 실제로 맞고 기계적으로도 확인됐는데, 사실 색상 선택의 문제라기보다 **강도(intensity)**의 문제임. 빈 랭킹 테이블이나 튜토리얼 메뉴까지 포함한 모든 화면이 실제 플레이와 똑같은 풀 채도 회전 발광을 그대로 돌리다 보니, 폭탄이나 그랜드 티츄 같은 진짜 극적인 순간이 대비될 조용한 기준선이 없음. 여기에 디자인 리뷰만으로는 못 잡아낼 두 번째 문제가 디텍터로 겹쳐서 발견됨 — 여러 텍스트/배경 조합이 WCAG 대비 기준을 큰 폭으로 못 맞추고, 그중 일부는 문자 그대로 "붉은색 위의 붉은 계열"임. 가장 큰 기회는 두 갈래로 나뉨: 실제 게임플레이를 제외한 곳의 앰비언트 강도를 낮추는 것, 그리고 대비 문제를 "빨간색을 줄이는 것"과는 별개의, 측정 가능한 접근성 작업으로 다루는 것.

## 잘 되어 있는 점

1. **그랜드 티츄 선언 모달**: 명확한 이지선다, 확정 전에 +200/−200 배점을 인라인으로 안내, "선언!"과 "패스"의 대비가 강함. 인터페이스에서 가장 잘 만들어진 고위험 결정 UI.
2. **튜토리얼 시스템**: 소요시간이 표시된 4개의 짧고 실습 중심인 레슨 + 완료 추적. 캐주얼 미니게임 허브 대부분이 아예 안 하는 투자.
3. **지속적인 상태 가독성**: 페이즈 배지, 상대별 카드 수 배지, 턴 표시, 평문 한국어 토스트 덕분에 플레이어가 방금 무슨 일이 있었는지 추측할 필요가 거의 없음.

## 우선순위 이슈

**[P1] 어디서나 풀 강도 빨간 앰비언트가 절대 안 쉼**
- **왜 문제인가**: `+page.svelte`의 `.page-background`(진한 빨강 방사형 그라디언트 `#7f1d1d → #450a0a → #1a0505` + 회전하는 빨강/황토/초록 콘 그라디언트 레이어)가 설정, 튜토리얼, 랭킹, 실제 플레이까지 **모든 화면 뒤에 동일한 강도로** 깔림. 디텍터가 컴포넌트 레벨에서도 독립적으로 이걸 뒷받침 — 라이브 테이블의 `#dc2626` 색상 박스섀도우 발광, 그리고 같은 붉은 발광 느낌을 강화하는 `gpt-thin-border-wide-shadow` 패턴(1px 보더 + 40px 블러). 게임플레이와 "메뉴 구경하기"가 똑같이 강렬해 보이니 아무것도 정점처럼 느껴지지 않고, 이게 사용자들이 말한 "부담스럽다"의 정체일 가능성이 매우 큼.
- **해결 방향**: 풀 채도/모션은 실제 게임플레이와 고위험 순간(그랜드 티츄, 폭탄, 승리)에만 남겨두기. 설정/랭킹/튜토리얼은 같은 팔레트 계열이되 강도를 훨씬 낮춘 화면으로.
- **추천 커맨드**: `$impeccable quieter`

**[P1] 광범위한 대비 실패 — 디텍터만 잡아낸 실제 접근성 리스크**
- **왜 문제인가**: 브라우저 증거에서 WCAG AA 기준(본문 4.5:1 / 큰 텍스트 3:1)에 크게 못 미치는 텍스트/배경 조합이 다수 발견됨: 설정 화면 — `#cbd5e1` on `#f0f0f0`(1.3:1), `#fbbf24` on `#c39c9c`(1.5:1), `#ffffff` on `#fbbf24`(1.7:1); 라이브 테이블 — `#fca5a5` on `#909090`(1.7:1), `#93c5fd` on `#909090`(1.8:1), `#d1d5db` on `#909090`(2.2:1), `#fbbf24` on `#787878`(2.6:1), `#ffffff` on `#3b82f6`(3.7:1), `#ffffff` on `#ef4444`(3.8:1). 이런 종류는 디자인 리뷰만으로는 "미학적으로 약간 아쉬운 정도"로 과소평가되기 쉽지만 실제로는 측정 가능한 명확한 실패임 — 저시력 사용자나 야외 밝은 곳에서 폰으로 보는 사람은 게임 상태 텍스트를 읽기 힘들어짐.
- **해결 방향**: 텍스트-색상 배경 조합 전체에 대비 검사를 한 번 돌리기. 특히 `#909090`/`#787878`/`#c39c9c` 같은 탁한 배경 위의 색상 텍스트를 우선적으로 — 배경을 어둡게 하거나 더 높은 대비의 텍스트 토큰으로 교체.
- **추천 커맨드**: `$impeccable audit`

**[P1] 카드 자체가 티츄 이름만 두른 일반 서양식 덱**
- **왜 문제인가**: `SUIT_NAMES`(옥/검/탑/별)는 데이터에만 존재하고, `CardComponent.svelte`의 `suitMap`은 그냥 클로버/스페이드/다이아몬드/하트 기호를 그림. 한 게임에서 수백 번씩 읽는 카드 페이스에 제품 고유의 정체성이 전혀 없음.
- **해결 방향**: 옥/검/탑/별에 맞는 고유한 글리프를 디자인해서, 덱 자체가 "이 게임"으로 보이게 하기 — 리스킨된 표준 덱이 아니라.
- **추천 커맨드**: `$impeccable adapt`

**[P2] "AI풍 클리셰" 장식 패턴이 일반화 인상을 더 키움**
- **왜 문제인가**: 카드 문제 외에도 디텍터가 그라디언트 텍스트 헤더 5건과 `flat-type-hierarchy`(폰트 크기가 13.3~19.2px에 몰려 있어 범위가 1.9:1밖에 안 됨)를 찾음 — 둘 다 의도적으로 만든 요소라기보다 기본값처럼 느껴지는 선택. 바로 옆에 진짜 고유한 금색/드래곤 시스템이 있는데, 이런 요소들은 의도가 아니라 "그냥 채워넣은 것"처럼 읽힘.
- **해결 방향**: 그라디언트 텍스트 헤더를 다른 곳에 이미 쓰는 단색 금색/크림 톤으로 교체. 헤딩/라벨/본문이 뭉치지 않고 뚜렷이 구분되는 계층이 되도록 타입 스케일을 넓히기.
- **추천 커맨드**: `$impeccable distill`

**[P2] 결정 순간에서 배점 안내와 대기 상태 표시가 일관되지 않음**
- **왜 문제인가**: 관련된 두 가지 문제. (1) 사람이 그랜드 티츄를 패스하면 모달은 닫히지만 페이즈 배지가 "그랜드 티츄"에 그대로 멈춰 있고 AI가 처리되는 동안 "상대방 결정 중" 같은 안내가 없어 앱이 멈춘 것처럼 보일 수 있음. (2) 스몰 티츄 확정 버튼은 "스몰 티츄!"만 적힌 한 번 탭하는 필(pill) 형태로, 그랜드 티츄 모달의 명시적인 배점 안내와 달리 +100/−100 배점이 인라인으로 안 보임 — 부주의한 플레이어가 같은 수준의 리마인더 없이 실제 페널티 리스크를 감수하게 됨.
- **해결 방향**: 그랜드 티츄 결정 후 짧은 대기 표시 추가(튜토리얼에 이미 있는 점 펄스 패턴 재사용). 스몰 티츄 버튼 근처에 +100/−100 배점을 그랜드 티츄와 같은 문구 패턴으로 인라인 노출.
- **추천 커맨드**: `$impeccable clarify`

## 페르소나별 레드플래그

**Jordan (첫 사용자)**: 튜토리얼을 건너뛰고 바로 게임에 들어가면, "카드 선택 → 슬롯 선택"의 2단계 교환 인터랙션을 "카드를 선택하세요"라는 작은 힌트 하나만 보고 마주하게 됨 — 이 2단계 제스처에 대한 인라인 설명이 없음. 드래곤/봉황/마작 아이콘의 의미는 튜토리얼에서만 배우고, 게임 중 참조할 범례가 없음.

**Sam (접근성 의존 사용자)**: 위의 대비 문제가 직격탄임 — 점수 값, 상대 라벨 같은 상태 표시 텍스트 중 일부가 1.3~2.6:1까지 떨어지는데, 최소 기준인 4.5:1에 한참 못 미침. 저시력이거나 화면 확대를 쓰는 사용자는 시력 정상인 사용자가 한눈에 읽는 게임 상태를 놓칠 수 있음.

**Riley (스트레스 테스터)**: 이미 배정된 교환 카드를 다시 탭하면 토글 방식으로 배정이 풀리는데, 다른 곳의 상태 변화 외에는 뚜렷한 피드백이 없어서 만지작거리는 중 어떤 카드가 현재 미배정 상태인지 놓치기 쉬움. 반대로, `beforeunload` 시점 자동 저장은 이 페르소나가 확실히 인정할 만한 강점.

## 사소한 관찰

- 파트너 전략 선택 그리드(2열에 5개 옵션)가 ≤4개 청킹 가이드라인을 넘고, 3번째 줄에 반쪽짜리 카드가 하나 남아 비대칭적으로 보임.
- `bounce-easing`이 카드 딜/선물 공개/점수 증가에서 동일한 오버슈트 곡선 2종으로 15번 등장 — 카드게임 특유의 의도된 "팝" 연출일 가능성이 있어 무조건 제거 대상이라기보다 의도적으로 판단할 사항.
- `layout-transition` 2건(`margin-left`, `width`)이 `transform` 대신 레이아웃을 트리거하는 속성을 애니메이션 — 추후 애니메이션 작업 때 가볍게 교체할 만한 성능 이슈.
- 소원(wish) 모달이 13개 랭크를 한 그리드에 평평하게 다 보여줌 — ≤4개 선택지 가이드라인을 벗어나지만, 티츄 룰 자체가 13개 랭크라 어느 정도는 불가피함. 내가 안 가진 랭크를 덜 강조하는 정도로 룰을 바꾸지 않고도 개선 가능.
- 랭킹 탭의 빈 상태("아직 이번 달 기록이 없습니다")는 깔끔하고 문구도 적절함.
- 모바일 뷰포트(390×844), 실제 트릭 플레이 중인 테이블, 소원 모달, 드래곤 선물 모달, 라운드 종료/게임 종료 모달은 **이번 실행에서 픽셀 단위로 확인되지 않음**(진행 중 개발 서버 문제로 두 번째 스크린샷 패스가 중단됨). 이 화면들에 대한 위 내용은 소스 코드 리뷰 기반이지 실제 렌더링 확인이 아니므로, 설정 화면/교환 단계 항목보다 확신도가 다소 낮음.

## 고려해볼 질문

1. 드래곤/금색 비주얼 언어가 항상 어디서나 시끄러운데, 그랜드 티츄나 폭탄, 마지막 트릭도 설정 화면보다 더 크게 느껴지지 않음. 게임 시작 화면이 조용하고 폭탄이 불꽃놀이처럼 느껴지면 이 게임은 어떤 느낌이 될까?
2. UI의 모든 강조색이 똑같은 빨강 위의 금색임 — CTA, 배지, 발광, 보더가 전부. 첫 사용자가 색만으로 "지금 해야 할 행동"과 "그냥 장식"을 구분 못 한다면, 실제로 그 신호를 전달하는 건 뭘까?
3. 플레이어가 게임 내내 쳐다보는 카드가 사실 티츄 옷을 입은 프랑스 덱인데, 옥/검/탑/별이 진짜로 옥/검/탑/별처럼 보이게 만드는 데 얼마가 들까?
