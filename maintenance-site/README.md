# 점검 안내 정적 사이트

서버가 멈춰 있는 동안 **서버 밖에서** 안내를 내보내기 위한 묶음이다.

## 왜 필요한가

앱(`static/offline.html` + 서비스워커)만으로는 빈틈이 있다. 서비스워커는 설치
없이 한 번 방문만 해도 깔리지만, 그래도 아래 사람들은 브라우저 기본 오류 화면을
본다:

- 배포 후 한 번도 안 들어온 사람
- 처음 오는 사람
- 시크릿 모드(iOS Safari는 서비스워커를 끈다)
- 사이트 데이터를 지운 사람

이 묶음을 외부 호스팅에 올리고 중단 기간에 DNS만 돌려두면 그 사람들도 안내를
본다. 서버가 살아 있는 동안에는 아무 영향이 없다 — DNS를 바꾸지 않으면 그냥
쓰이지 않는 정적 파일일 뿐이다.

## 들어 있는 것

**업로드할 것은 `public/` 폴더뿐이다.** 이 README는 올리지 않는다 — Pages는
폴더에 있는 파일을 전부 공개하므로, 같이 올리면 이 문서가 `/README.md`로
누구나 볼 수 있게 된다.

| `public/` 안의 파일 | 역할 |
|---|---|
| `index.html` | 안내 페이지 (`static/offline.html`과 같은 내용) |
| `404.html` | 같은 내용. 호스팅이 없는 경로에 이걸 쓴다 |
| `_redirects` | `/* → /index.html 200`. 북마크가 `/collection` 같은 걸 가리켜도 안내가 뜨게 |
| `favicon.png`, `icon-192.png` | 페이지가 참조하는 아이콘 |

서비스워커는 **일부러 넣지 않았다.** 점검 호스트가 서비스워커를 심으면 회원
기기에 안내 페이지가 캐시로 박혀, 복구 후에도 계속 뜰 수 있다.

## 문구 고치기

`index.html`과 `404.html` 두 파일 모두에서 `↓↓↓ 고칠 곳` 블록을 고친다.
(원본은 `static/offline.html`이다 — 거기를 고친 뒤 다시 복사하는 편이 안전하다.)

```sh
cp ../static/offline.html public/index.html
cp public/index.html public/404.html
```

## 올리기 (두 주소 공통)

1. Cloudflare → Workers & Pages → Create
   화면 맨 아래 **"Continue to Pages"** 를 누른다. 위쪽의 "Upload your static
   files"를 고르면 Workers로 만들어지는데, Workers의 커스텀 도메인은 도메인
   전체가 Cloudflare 존으로 올라가 있어야 한다. Pages의 커스텀 도메인만 외부
   DNS(afraid.org)를 그대로 두고 CNAME 하나로 연결할 수 있다.
2. Upload assets → **`public/` 폴더만** 업로드. 프로젝트 이름은 아무거나
   (예: `honnol-maintenance`)
3. 배포되면 `https://<프로젝트>.pages.dev`로 열어서 안내가 뜨는지 확인
4. **DNS는 아직 바꾸지 않는다.** 여기까지가 준비다

여기까지는 서비스에 아무 영향이 없다.

## 돌리기 — damonpyo.mooo.com (주로 쓰는 주소)

확인된 조건:

| 항목 | 값 | 뜻 |
|---|---|---|
| A 레코드 | 집 서버 IP | 전환 전에 **반드시 메모**해 둘 값 |
| TTL | **3600초 (1시간)** | 전환이 최대 1시간 걸린다 |
| `mooo.com` CAA | 없음 | 어느 CA든 인증서를 낼 수 있다 |
| HSTS 헤더 | 없음 | https 강제 고정은 걸려 있지 않다 |

**먼저 해야 할 두 가지가 있다. 둘 다 중단 당일이 아니라 미리 해야 한다.**

### ① TTL을 내려둔다 (중단 며칠 전)

TTL이 3600이면 레코드를 바꿔도 최대 1시간 동안 옛 IP를 쓰는 사람이 있다.
afraid.org에서 TTL을 낮출 수 있으면 300 정도로 내려둔다. **TTL 변경 자체가
옛 TTL만큼 걸려 퍼지므로**, 중단 최소 하루 전에 해야 효과가 있다.
(무료 계정에서 TTL이 고정이면 그냥 "최대 1시간 걸린다"를 받아들인다.)

### ② 인증서를 미리 받아둔다

이게 중요하다. 북마크·PWA가 `https://damonpyo.mooo.com`을 쓰므로, 전환된 쪽에
그 호스트네임용 인증서가 **없으면 브라우저가 인증서 경고를 띄운다.** 그건
"연결할 수 없음"보다 나쁘다 — 회원은 사이트가 해킹당한 줄 안다.

Pages → 프로젝트 → Custom domains → `damonpyo.mooo.com` 추가. 이때 Cloudflare가
검증 방법을 알려준다:

- **TXT 레코드를 요구하면 그대로 추가한다.** 트래픽에 영향이 없으므로 미리
  인증서까지 받아둘 수 있다. 가장 깔끔한 경로다.
- **CNAME을 요구하면** 그 순간 주소가 Pages로 넘어가므로 미리 할 수 없다.
  그 경우는 아래 "CNAME만 가능할 때"를 본다.

### 중단할 때

1. afraid.org에서 지금 들어 있는 A 레코드 값을 **메모**해 둔다
   (`dig +short damonpyo.mooo.com` 으로도 확인된다)
2. A 레코드를 지우고 CNAME `damonpyo.mooo.com → <프로젝트>.pages.dev` 추가
3. TTL만큼 기다리면 전원이 안내 페이지를 본다

### 복구할 때

4. CNAME을 지우고 A 레코드를 되돌린다.
   **회선이 바뀌면 IP도 바뀐다** — 1번에서 메모한 옛 IP를 그대로 넣으면 안 된다.
   새 IP를 확인한 뒤 넣는다.

### CNAME만 가능할 때 (인증서를 미리 못 받는 경우)

전환 직후 몇 분간 인증서가 없어 경고가 뜰 수 있다. 선택지는 둘이다.

- **그냥 건너뛴다.** 앱 쪽 안내(서비스워커)가 이미 거의 모든 회원을 덮는다.
  남는 사람은 "처음 오는 사람 / 시크릿 모드 / 데이터 지운 사람"뿐이고, 그들이
  보는 것은 브라우저 기본 오류 화면이다 — 인증서 경고보다는 낫다.
- **서버를 끄기 전에 미리 전환한다.** 서버가 아직 살아 있는 동안 CNAME을 바꿔
  인증서가 나오는 것까지 확인한다. 대신 그 시점부터 실제 서비스가 안내 페이지로
  바뀌므로, 정말 문을 닫은 뒤에 해야 한다.

## 돌리기 — honnol.org

이쪽은 DNS가 이미 Cloudflare에 있고 TTL이 300초라 훨씬 쉽다. 인증서도 같은
계정의 존이라 자동으로 나온다.

1. Cloudflare → DNS → 지금 들어 있는 A 레코드 값을 메모
2. 지우고 CNAME `honnol.org → <프로젝트>.pages.dev` (프록시 ON / 주황 구름)
3. 5분 뒤 적용. 복구는 역순(새 IP 주의)

프록시(주황 구름)를 켜는 것은 **전환할 때만**이다. 평소에 켜두면 SSE 같은 실시간
연결이 Cloudflare를 거치게 되어 따로 확인해야 한다 — 중단 직전에 건드릴 일이
아니다.
