# 점검 안내 정적 사이트

서버가 멈춰 있는 동안 **서버 밖에서** 안내를 내보내기 위한 묶음이다.

## 왜 필요한가

앱(`static/offline.html` + 서비스워커)만으로는 빈틈이 있다. 서비스워커는 설치
없이 한 번 방문만 해도 깔리지만, 그래도 아래 사람들은 브라우저 기본 오류 화면을
본다:

- 배포 후 한 번도 안 들어온 사람
- 처음 오는 사람
- 시크릿 모드(iOS Safari는 서비스워커를 끈다)
- 사이트 데이터를 지운 사람

이 묶음을 외부 호스팅에 올리고 중단 기간에 DNS만 돌려두면 그 사람들도 안내를
본다. 서버가 살아 있는 동안에는 아무 영향이 없다 — DNS를 바꾸지 않으면 그냥
쓰이지 않는 정적 파일일 뿐이다.

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `index.html` | 안내 페이지 (`static/offline.html`과 같은 내용) |
| `404.html` | 같은 내용. 호스팅이 없는 경로에 이걸 쓴다 |
| `_redirects` | `/* → /index.html 200`. 북마크가 `/collection` 같은 걸 가리켜도 안내가 뜨게 |
| `favicon.png`, `icon-192.png` | 페이지가 참조하는 아이콘 |

서비스워커는 **일부러 넣지 않았다.** 점검 호스트가 서비스워커를 심으면 회원
기기에 안내 페이지가 캐시로 박혀, 복구 후에도 계속 뜰 수 있다.

## 문구 고치기

`index.html`과 `404.html` 두 파일 모두에서 `↓↓↓ 고칠 곳` 블록을 고친다.
(원본은 `static/offline.html`이다 — 거기를 고친 뒤 다시 복사하는 편이 안전하다.)

```sh
cp ../static/offline.html index.html
cp index.html 404.html
```

## 올리고 돌리는 방법 (Cloudflare 기준)

honnol.org의 DNS는 이미 Cloudflare에 있다(TTL 300초). 그래서 인증서 발급이
자동으로 되고, 전환이 5분이면 끝난다.

**미리 (서버 멈추기 전):**

1. Cloudflare → Workers & Pages → Create → Pages → Upload assets
2. 이 폴더를 그대로 업로드. 프로젝트 이름은 아무거나(예: `honnol-maintenance`)
3. 배포되면 `https://<프로젝트>.pages.dev`로 열어서 안내가 뜨는지 확인
4. **DNS는 아직 바꾸지 않는다.** 여기까지가 준비다

**중단할 때:**

5. Cloudflare → DNS → `honnol.org`의 A 레코드(`58.79.132.122`)를 메모해 둔다
6. 그 레코드를 지우고, 대신 CNAME `honnol.org → <프로젝트>.pages.dev` 를 만든다
   (프록시 ON / 주황 구름)
7. 5분 뒤부터 모두 안내 페이지를 본다

**복구할 때:**

8. CNAME을 지우고 5번에서 메모한 A 레코드를 되돌린다
   (이사로 IP가 바뀌었으면 **새 IP**로 넣는다 — 아래 주의 참고)

## 주의

- **IP가 바뀐다.** 회선이 바뀌면 `58.79.132.122`도 바뀐다. 복구할 때 예전 IP를
  그대로 넣으면 안 된다. 새 IP를 확인한 뒤 넣는다.
- `damonpyo.mooo.com`은 FreeDNS에 있어서 따로 돌려야 한다. 회원이 주로 쓰는
  주소가 `honnol.org`라면 거기만 해도 된다.
- 프록시를 켜는 것(주황 구름)은 전환할 때만이다. 평소에 켜두면 SSE 같은 실시간
  연결이 Cloudflare를 거치게 되어 동작을 따로 확인해야 한다 — 중단 직전에
  건드릴 일은 아니다.
